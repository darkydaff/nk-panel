# Database and Migrations

The Nk-VPN Panel uses a relational database (MySQL/MariaDB by default) for persistent storage.

## Migrations System

Database schema updates are handled via raw SQL scripts located in the `migrations/` directory.

-   **Execution:** These scripts are automatically run in alphabetical/numerical order when the Docker database container is first initialized.
-   **Idempotency:** When writing new migrations, use `ON DUPLICATE KEY UPDATE` or `IF NOT EXISTS` syntax where applicable to ensure migrations can be run safely against an existing database without throwing errors.
-   **Structure:**
    -   `001_init.sql`: The foundational schema containing all primary tables.
    -   `002_translations_*.sql`: Localized translation strings.
    -   `007+`: Subsequent schema modifications, new tables, and feature additions.

To manually run a migration inside the Docker environment:
```bash
docker-compose exec -T db mysql -uroot -prootpassword amnezia_panel < migrations/012_add_user_roles.sql
```

## Core Tables Overview

### `users`
Stores administrator and normal user accounts.
-   `email`: Login email.
-   `password_hash`: Bcrypt hashed password.
-   `role`: Determines access level (`admin` vs `user`).

### `vpn_servers`
Stores the remote VPN server configurations.
-   `host`, `port`, `username`, `password`: SSH credentials used by the panel to connect and deploy/manage configurations.
-   `secret_token`: A unique token used by the remote server's monitoring agent to push stats back to the panel.
-   `mimicry_type`: E.g., `quic`, used by AmneziaWG for obfuscation.
-   `show_in_bot`, `allowed_clients`, `blocked_clients`: Telegram bot access control lists.

### `vpn_clients`
Stores individual peer configurations deployed on the VPN servers.
-   `server_id`: Foreign key to `vpn_servers`.
-   `public_key`, `private_key`, `client_ip`: WireGuard/AmneziaWG network details.
-   `ext_client_code`: (Optional) Foreign key linking this config to a billing/subscription entity in `ext_clients`.
-   `bytes_sent`, `bytes_received`, `speed_up_kbps`, `speed_down_kbps`: Traffic and current speed metrics.
-   `traffic_limit`: Optional hard cap on data usage (in bytes).
-   `expires_at`: Optional expiration date.

### `ext_clients`
A synchronized local cache of a potential external billing/subscription database (e.g., PostgreSQL).
-   `code`: The unique identifier (often used as a subscription code).
-   `func`: Status (e.g., `WORK`, `PAUSE`).
-   `start_date`, `sub`: Used to calculate expiration based on subscription duration.
-   `router`: An optional flag or associated router identifier.

### `routers`
Stores Keenetic router devices linked to user accounts.
-   `ext_client_code`: The client code this router is associated with.
-   `domain`, `login`, `password`: Credentials to access the router's CLI interface.
-   `status`: E.g., `active`, `pending`, `offline`, `error`.

### `routing_groups`
Stores predefined lists of domains/IP subnets for split tunneling.
-   `name`: Group name.
-   `content`: A newline-separated list of domains or CIDR blocks.

### `client_metrics` & `server_metrics`
Time-series tables for storing historical traffic and speed data, used for dashboard charts.

### `settings` & `system_settings`
Key-value stores for application configuration (e.g., Telegram bot tokens, backup settings, sync timestamps). `settings` supports namespaces and user-specific configurations, while `system_settings` is global.

### `server_backups`
Records metadata about backups generated by the system.
-   `backup_scope`: Whether it's a `panel` (full system), `server` (individual), or `ext_db` backup.
-   `backup_path`: Path on disk where the archive is stored before (or alongside) being uploaded to Telegram.

### `bot_activity_logs`
An audit trail of actions taken by users interacting with the Telegram client bot (e.g., `view_menu`, `change_server_success`, `unauthorized`).
